Introduction

What Are Closures?

Functions that carry their own backpack of variables wherever they go.

What's a Closure?

A closure is a function defined inside another function that remembers variables from the outer function's scope — even after the outer function has finished running. The inner function "closes over" those variables, keeping them alive. That's why it's called a closure.

outer() returns inner → inner still has access to outer's variables

Foundations

Key Concepts

Four things you need to know before closures make sense.

🏠

Nested Functions

You can define a function inside another function. The inner function can access everything from the outer function's scope — its variables, parameters, everything.

def outer():
  def inner():
    ...
  return inner

💡 The inner function only exists inside outer — you can't call it from outside directly.

📦

Free Variables

A "free variable" is a variable used inside the inner function but defined in the outer function. It's not local to inner, and it's not global — it lives in between. Python stores these in a special __closure__ attribute.

def outer():
  x = 10 # free variable
  def inner():
    return x

💡 Check them with: func.__code__.co_freevars

🧠

Variable Lifetime Extension

Normally, a function's local variables die when the function returns. But if an inner function references them, Python keeps them alive in a "cell object". The closure holds a reference to the cell, not a copy of the value.

fn = outer() # outer is done
fn() # but x is still alive!

💡 This is why closures can "remember" — the variable isn't garbage collected.

🔗

Returning Functions

A closure only happens when you return the inner function (or pass it somewhere). If you just call it inside outer, there's no closure — it's just a regular nested call.

def outer(msg):
  def inner(): print(msg)
  return inner # ← closure created here

💡 The key moment: returning or storing the inner function for later use.

Hands-On

Code Examples

Start simple, then build up. Each example adds one new idea.

Example 1: Basic Closure

The simplest closure — an inner function that remembers a variable from its parent.

basic_closure.py 
def make_greeter(name):
    def greet():
        print(f"Hello, {name}!")
    return greet

hello_alice = make_greeter("Alice")
hello_bob = make_greeter("Bob")

hello_alice()
hello_bob()
Hello, Alice! Hello, Bob!

Example 2: Counter — Closure with Mutable State

Closures can hold state that persists between calls — like a private variable that only the inner function can touch.

counter_closure.py 
def make_counter(start=0):
    count = [start]  # list so we can mutate it

    def increment():
        count[0] += 1
        return count[0]

    return increment

counter = make_counter()
print(counter())  # 1
print(counter())  # 2
print(counter())  # 3
1 2 3

Example 3: Real-World — Configuration Factory

Create specialized functions by "baking in" configuration. This is how you avoid passing the same arguments over and over.

logger_factory.py 
def make_logger(prefix, level="INFO"):
    def log(message):
        print(f"[{level}] {prefix}: {message}")
    return log

db_log = make_logger("DATABASE")
api_log = make_logger("API", "DEBUG")

db_log("Connection established")
api_log("Request received at /users")
db_log("Query took 0.3s")
[INFO] DATABASE: Connection established [DEBUG] API: Request received at /users [INFO] DATABASE: Query took 0.3s

Example 4: Advanced — Rate Limiter Using Closure

A closure that tracks timestamps to limit how often a function can be called — no class needed.

rate_limiter.py 
import time

def rate_limit(min_interval):
    """Only allow calls every min_interval seconds."""
    last_called = [0]

    def decorator(func):
        def wrapper(*args, **kwargs):
            elapsed = time.time() - last_called[0]
            if elapsed < min_interval:
                print(f"⏳ Rate limited. Wait {min_interval - elapsed:.1f}s")
                return None
            last_called[0] = time.time()
            return func(*args, **kwargs)
        return wrapper
    return decorator

@rate_limit(2.0)
def send_email(to):
    print(f"✉️ Email sent to {to}")

send_email("alice@example.com")
send_email("bob@example.com")  # blocked!
✉️ Email sent to alice@example.com ⏳ Rate limited. Wait 1.9s
In Production

Real-World Use Cases

Closures are everywhere — you're probably already using them without knowing it.

🎨

Decorators

Every decorator is a closure. The wrapper function closes over the original function and adds behavior around it.

🏭

Factory Functions

Create specialized functions on the fly — like make_multiplier(3) that returns a function which triples any number.

🔐

Data Encapsulation

Hide variables from the outside world. Only the inner function can read or modify them — like private fields without a class.

📡

Callbacks & Event Handlers

When you pass a function to run later (like an onClick handler), it often needs to remember context from when it was created.

⚙️

Partial Application

Pre-fill some arguments of a function and return a simpler version. functools.partial does this under the hood.

🧪

Test Fixtures & Mocks

Create test helpers that remember setup state — like a mock that counts how many times it was called.

📊

Memoization / Caching

Store computed results in a dictionary that lives in the closure. Next time the same input comes in, return the cached result.

🔄

Middleware Chains

Each middleware function closes over the next one in the chain, creating a pipeline of processing steps.

⏱️

Debounce / Throttle

Track the last call time in a closure variable to prevent a function from firing too often — common in UI and API code.

Interview Questions

Questions you'll likely get asked. Click to reveal the answers.

1What is a closure in Python?▼

A closure is a nested function that remembers and has access to variables from its enclosing function's scope, even after that outer function has finished executing. It "closes over" the free variables.

💡 Give a simple example: a function that returns another function which uses a variable from the outer scope.
2What are the three conditions for a closure to exist?▼

1) There must be a nested function. 2) The inner function must reference a variable from the outer function. 3) The outer function must return the inner function (or store it somewhere for later use).

💡 If any of these three is missing, it's not a closure — just a regular nested function.
3How do you inspect a closure's captured variables?▼

Use func.__closure__ to see the cell objects, and func.__closure__[i].cell_contents to get the actual values. Use func.__code__.co_freevars to see the variable names.

💡 Showing you know about __closure__ and co_freevars proves you understand the internals, not just the concept.
4What's the "late binding" gotcha with closures in loops?▼

If you create closures inside a loop, they all share the same variable — and by the time you call them, the loop is done and the variable has its final value. Fix it by passing the variable as a default argument: def inner(i=i).

💡 This is the #1 closure bug. Show the broken version and the fix side by side.
5Can a closure modify the captured variable?▼

Yes, but you need the nonlocal keyword (Python 3+). Without it, assigning to the variable creates a new local variable instead of modifying the captured one. Alternatively, use a mutable container like a list.

💡 Explain the difference between nonlocal (enclosing scope) and global (module scope).
6What's the difference between a closure and a class with one method?▼

They're functionally similar — both hold state and expose behavior. Closures are lighter (no class boilerplate) and better for simple cases. Classes are better when you need multiple methods, inheritance, or complex state.

💡 Quote: "A closure is a poor man's object. An object is a poor man's closure." — shows you understand the duality.
7How are closures related to decorators?▼

Every decorator uses a closure. The wrapper function is an inner function that closes over the original function (passed as an argument to the decorator). Without closures, decorators wouldn't work.

💡 Walk through a simple decorator and point out exactly where the closure is.
8Do closures cause memory leaks?▼

They can, if the closure accidentally holds a reference to a large object that should have been garbage collected. Python only keeps variables alive that the inner function actually references — but if you reference a big object, it stays in memory as long as the closure exists.

💡 Mention that you can use del or weak references to avoid holding large objects unnecessarily.
