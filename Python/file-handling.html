Introduction

File I/O in Python

Everything you need to know about reading, writing, and managing files safely.

The Core Pattern

File handling in Python follows a simple pattern: open a file, do something with it (read/write), then close it. The with statement handles closing automatically — even if your code crashes. Always use it.

with open("file.txt", "r") as f:  ← opens, auto-closes, exception-safe

📝 Text Mode (default)

Returns str objects. Handles encoding (UTF-8 by default) and newline translation (\r\n → \n on Windows).

# Text mode
open("data.txt", "r")
open("data.txt", "r", encoding="utf-8")

Use for: .txt, .csv, .json, .html, .py, .log

🔢 Binary Mode

Returns bytes objects. No encoding/decoding, no newline translation. Raw data as-is.

# Binary mode
open("image.png", "rb")
open("data.bin", "wb")

Use for: .png, .jpg, .pdf, .zip, .exe, .mp3

Read, Write, and Append — The Big Three

The three operations you'll use 95% of the time.

read_write_append.py 
# ✍️ WRITE — creates file or erases existing content
with open("notes.txt", "w") as f:
    f.write("Line 1: Hello\n")
    f.write("Line 2: World\n")
    f.writelines(["Line 3: Foo\n", "Line 4: Bar\n"])

# 📖 READ — multiple ways to read
with open("notes.txt", "r") as f:
    content = f.read()        # entire file as one string
    print(content)

with open("notes.txt", "r") as f:
    lines = f.readlines()     # list of lines (includes \n)
    print(lines[0])            # "Line 1: Hello\n"

with open("notes.txt", "r") as f:
    first_line = f.readline() # just the first line

# ➕ APPEND — adds to end without erasing
with open("notes.txt", "a") as f:
    f.write("Line 5: Appended!\n")

# Verify
with open("notes.txt") as f:
    print(f"Total lines: {len(f.readlines())}")
Line 1: Hello Line 2: World Line 3: Foo Line 4: Bar Total lines: 5

⚡ Buffering — When Data Actually Hits Disk

When you call f.write(), data goes to an in-memory buffer first — not directly to disk. Python flushes the buffer when it's full, when you close the file, or when you call f.flush() manually.

buffering=NBuffer of N bytesCustom chunk sizes

Working with Files

File pointers, seek/tell, line-by-line reading, and chunk processing.

The File Pointer — Your Position in the File
Every open file has an invisible cursor that tracks where you are. Reading advances it forward.

H e l l o ,  W o r l d !
↑ ← pointer starts at position 0

After f.read(5): reads "Hello"
H e l l o ,  W o r l d !
          ↑ ← pointer now at position 5

f.tell() → returns 5 (current position)
f.seek(0) → moves pointer back to start

seek() and tell() — Navigate Within a File

Move the file pointer to any position. Essential for re-reading or skipping sections.

seek_tell.py 
with open("notes.txt", "r") as f:
    # Read first 10 characters
    chunk = f.read(10)
    print(f"Read: '{chunk}'")
    print(f"Position: {f.tell()}")  # 10

    # Go back to the beginning
    f.seek(0)
    print(f"After seek(0): {f.tell()}")  # 0

    # Read again from start
    print(f"Re-read: '{f.read(5)}'")

    # Jump to position 20
    f.seek(20)
    print(f"From pos 20: '{f.read(10)}'")

# seek(offset, whence):
# whence=0 → from start (default)
# whence=1 → from current position (binary mode only)
# whence=2 → from end (binary mode only)

# Read last 20 bytes of a binary file
with open("notes.txt", "rb") as f:
    f.seek(-20, 2)  # 20 bytes before end
    print(f"Last 20 bytes: {f.read()}")
Read: 'Line 1: He' Position: 10 After seek(0): 0 Re-read: 'Line ' From pos 20: 'orld\nLine ' Last 20 bytes: b'Line 5: Appended!\n'

Line-by-Line & Chunk Reading — Handling Large Files

Never load a 10GB file into memory at once. Iterate line by line or read in chunks.

large_files.py 
# ✅ BEST: Iterate line by line (memory efficient)
# Only one line in memory at a time — works for ANY file size
with open("huge_log.txt", "r") as f:
    for line_num, line in enumerate(f, 1):
        if "ERROR" in line:
            print(f"Line {line_num}: {line.strip()}")

# ✅ Chunk reading — for binary files or custom processing
def read_in_chunks(filepath, chunk_size=8192):
    """Read a file in fixed-size chunks."""
    with open(filepath, "rb") as f:
        while True:
            chunk = f.read(chunk_size)
            if not chunk:
                break
            yield chunk

# Process a large file without loading it all
total_size = 0
for chunk in read_in_chunks("large_file.bin"):
    total_size += len(chunk)
print(f"File size: {total_size:,} bytes")

# ❌ BAD: Don't do this for large files!
# content = f.read()  ← loads ENTIRE file into RAM
# lines = f.readlines()  ← same problem

Memory rule: for line in f: uses ~1 line of memory. f.read() uses memory equal to the file size. For a 5GB log file, that's the difference between 100 bytes and 5GB of RAM.

import csv

# ✍️ Write CSV
data = [

with open("users.csv", "r") as f:
    reader = csv.reader(f)
    header = next(reader)  # skip header row
    for row in reader:
        print(f"{row[0]} is {row[1]} from {row[2]}")

# 📖 Read CSV — as dictionaries (best for named columns)
with open("users.csv", "r") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(f"{row['name']}: {row['city']}")

# ✍️ Write CSV from dicts
users = [{"name": "Dave", "age": 30}, {"name": "Eve", "age": 25}]
with open("output.csv", "w", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "age"])
    writer.writeheader()
    writer.writerows(users)

JSON Handling — Structured Data Exchange

The json module converts between Python dicts/lists and JSON strings/files.

json_handling.py 
import json

# Python dict → JSON file
config = {
    "app_name": "MyApp",
    "version": "2.1.0",
    "debug": False,
    "database": {
        "host": "localhost",
        "port": 5432,
        "name": "mydb"
    },
    "allowed_hosts": ["localhost", "0.0.0.0"]
}

# ✍️ Write JSON (dump to file)
with open("config.json", "w") as f:
    json.dump(config, f, indent=2)  # indent for readability

# 📖 Read JSON (load from file)
with open("config.json", "r") as f:
    loaded = json.load(f)

print(f"App: {loaded['app_name']}")
print(f"DB port: {loaded['database']['port']}")

# String conversion (no file involved)
json_string = json.dumps(config, indent=2)  # dict → string
parsed = json.loads(json_string)              # string → dict

# Handle special types with custom encoder
from datetime import datetime

class DateEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, datetime):
            return obj.isoformat()
        return super().default(obj)

data = {"event": "deploy", "time": datetime.now()}
print(json.dumps(data, cls=DateEncoder))
App: MyApp DB port: 5432 {"event": "deploy", "time": "2026-05-31T10:30:00.123456"}

dump vs dumps: json.dump() writes to a file. json.dumps() returns a string. Same for load() (file) vs loads() (string). The "s" stands for "string."

Best Practices

Safe File Handling

The with statement, resource cleanup, and exception-safe patterns.

The with Statement — Why It Matters

The with statement is a context manager that guarantees the file is closed — even if an exception occurs. Without it, a crash between open() and close() leaves the file handle open, potentially corrupting data or leaking resources.

❌ Unsafe — file might not close

f = open("data.txt")
data = f.read()  # if this crashes...
f.close()       # ...this never runs!

✅ Safe — always closes

with open("data.txt") as f:
  data = f.read()
# auto-closed here, even on crash

Exception-Safe File Handling

Handle common file errors gracefully — missing files, permission issues, encoding problems.

exception_safe.py 
import os

# Pattern 1: Handle specific file errors
def read_config(filepath):
    """Read a config file with proper error handling."""
    try:
        with open(filepath, "r", encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        print(f"❌ File not found: {filepath}")
        return None
    except PermissionError:
        print(f"🔒 No permission to read: {filepath}")
        return None
    except UnicodeDecodeError:
        print(f"⚠️ Encoding error — try binary mode")
        return None

# Pattern 2: Safe write with atomic replacement
import tempfile

def safe_write(filepath, content):
    """Write atomically — file is never half-written."""
    dir_name = os.path.dirname(filepath) or "."
    try:
        # Write to temp file first
        with tempfile.NamedTemporaryFile(
            mode="w", dir=dir_name, delete=False
        ) as tmp:
            tmp.write(content)
            tmp_path = tmp.name
        # Rename atomically (all-or-nothing)
        os.replace(tmp_path, filepath)
    except Exception:
        # Clean up temp file on failure
        if os.path.exists(tmp_path):
            os.unlink(tmp_path)
        raise

# Pattern 3: Check before opening
filepath = "data.txt"
if os.path.exists(filepath) and os.path.isfile(filepath):
    with open(filepath) as f:
        print(f.read())
else:
    print("File doesn't exist")

EAFP vs LBYL: Python prefers "Easier to Ask Forgiveness than Permission" (try/except) over "Look Before You Leap" (if/else checks). Use try/except for file operations — the file could disappear between your check and your open.

Example 1: Log File Analyzer

Process a large log file line by line — count errors, extract timestamps, memory efficient.

log_analyzer.py 
from collections import Counter

def analyze_log(filepath):
    """Analyze a log file — memory efficient for any size."""
    stats = Counter()
    errors = []

    try:
        with open(filepath, "r") as f:
            for line_num, line in enumerate(f, 1):
                # Count log levels
                if "ERROR" in line:
                    stats["errors"] += 1
                    errors.append((line_num, line.strip()))
                elif "WARNING" in line:
                    stats["warnings"] += 1
                else:
                    stats["info"] += 1
                stats["total"] += 1

    except FileNotFoundError:
        print(f"Log file not found: {filepath}")
        return None

    return {"stats": dict(stats), "recent_errors": errors[-5:]}

result = analyze_log("app.log")
if result:
    print(f"Total lines: {result['stats']['total']}")
    print(f"Errors: {result['stats'].get('errors', 0)}")
Total lines: 15234 Errors: 42

Example 2: JSON Config Manager with Defaults

Load config from JSON, merge with defaults, save changes back — a common application pattern.

config_manager.py 
import json
import os

class ConfigManager:
    DEFAULTS = {
        "theme": "dark",
        "language": "en",
        "auto_save": True,
        "max_retries": 3,
    }

    def __init__(self, filepath):
        self.filepath = filepath
        self.config = self._load()

    def _load(self):
        """Load config, falling back to defaults."""
        if os.path.exists(self.filepath):
            with open(self.filepath, "r") as f:
                user_config = json.load(f)
            return {**self.DEFAULTS, **user_config}
        return self.DEFAULTS.copy()

    def get(self, key, default=None):
        return self.config.get(key, default)

    def set(self, key, value):
        self.config[key] = value
        self._save()

    def _save(self):
        with open(self.filepath, "w") as f:
            json.dump(self.config, f, indent=2)

# Usage
cfg = ConfigManager("settings.json")
print(cfg.get("theme"))       # "dark" (default)
cfg.set("theme", "light")   # saves to file
print(cfg.get("theme"))       # "light"
dark light

Example 3: CSV Data Pipeline — Filter and Transform

Read a CSV, filter rows, transform data, write results — a common ETL pattern.

csv_pipeline.py 
import csv

def process_sales(input_file, output_file, min_amount=100):
    """Filter sales above threshold and add tax column."""
    processed = 0

    with open(input_file, "r") as infile, \
         open(output_file, "w", newline="") as outfile:

        reader = csv.DictReader(infile)
        fieldnames = reader.fieldnames + ["tax", "total"]
        writer = csv.DictWriter(outfile, fieldnames=fieldnames)
        writer.writeheader()

        for row in reader:
            amount = float(row["amount"])
            if amount >= min_amount:
                row["tax"] = round(amount * 0.1, 2)
                row["total"] = round(amount * 1.1, 2)
                writer.writerow(row)
                processed += 1

    print(f"Processed {processed} sales above ${min_amount}")

# Multiple files open at once with 'with' — both auto-close
process_sales("sales.csv", "filtered_sales.csv", min_amount=50)
Processed 847 sales above $50

Interview Questions

Common file handling questions. Click to reveal answers.

1 What's the difference between "r", "w", and "a" modes? ▼

"r" = read only (file must exist). "w" = write only (creates file or erases existing content). "a" = append (creates file or adds to end without erasing). The critical difference: "w" destroys existing data, "a" preserves it.

💡 Common mistake: using "w" when you meant "a" — and accidentally erasing your entire file. Always double-check the mode.
2 Why should you always use with open() instead of open() + close()? ▼

The with statement guarantees the file is closed even if an exception occurs between open and close. Without it, a crash leaves the file handle open — potentially corrupting data, leaking file descriptors, or preventing other programs from accessing the file.

Under the hood, with calls __enter__() on open and __exit__() when the block ends (which calls f.close()). It's a context manager pattern.

💡 There's no good reason to NOT use with. It's shorter, safer, and more Pythonic.
3 How do you read a very large file without running out of memory? ▼

Iterate line by line with for line in f: — this loads only one line at a time regardless of file size. For binary files, read in fixed chunks: while chunk := f.read(8192):. Never use f.read() or f.readlines() on large files — they load everything into RAM.

💡 for line in f: is both memory-efficient AND fast — Python's file iterator is implemented in C and uses internal buffering.
4 What's the difference between text mode and binary mode? ▼

Text mode ("r", "w"): returns str, handles encoding (UTF-8 default), translates newlines (\r\n → \n on Windows). Binary mode ("rb", "wb"): returns bytes, no encoding, no newline translation — raw data as-is.

Use text for human-readable files (.txt, .csv, .json). Use binary for everything else (images, PDFs, executables, compressed files).

💡 If you get UnicodeDecodeError, you're probably opening a binary file in text mode. Switch to "rb".
5 What do seek() and tell() do? ▼

tell() returns the current position of the file pointer (in bytes). seek(offset, whence) moves the pointer to a specific position. whence=0 means from start, 1 from current position (binary only), 2 from end (binary only).

Use case: reading a file header, then seeking to a specific offset to read data. Or re-reading a file from the beginning without reopening it.

💡 After f.read(), the pointer is at the end. To read again, you need f.seek(0) to go back to the start.
6 What's the difference between json.dump() and json.dumps()? ▼

json.dump(obj, file) writes JSON directly to a file object. json.dumps(obj) returns a JSON string. Same for reading: json.load(file) reads from a file, json.loads(string) parses a string. The "s" stands for "string."

💡 Use dump/load when working with files. Use dumps/loads when working with API responses, network data, or in-memory strings.
7 How do you handle file encoding issues? ▼

Always specify encoding explicitly: open("file.txt", encoding="utf-8"). If you get UnicodeDecodeError, the file might use a different encoding (latin-1, cp1252, etc.). Use errors="replace" or errors="ignore" as a fallback, or detect encoding with the chardet library.

# Safe reading with fallback
open("file.txt", encoding="utf-8", errors="replace")
💡 UTF-8 handles 99% of cases. If you're reading old Windows files, try encoding="cp1252". For CSV from Excel, try encoding="utf-8-sig" (handles BOM).
8 What is buffering and when would you change it? ▼

Buffering means Python collects writes in memory and flushes them to disk in batches (default ~8KB). This is faster than writing every byte individually. You'd change it when you need: real-time logging (buffering=1 for line-buffered), or immediate writes (f.flush() after each write).

buffering=0 (unbuffered) is only available in binary mode. For text files, the minimum is line-buffered (buffering=1).

💡 If your log file appears empty until the program exits, it's a buffering issue. Use flush=True in print() or f.flush() after writes.
9 How do you write to a file atomically (all-or-nothing)? ▼

Write to a temporary file first, then rename it to the target path using os.replace(). Renaming is atomic on most filesystems — the file is either fully old or fully new, never half-written. This prevents data corruption if your program crashes mid-write.

# Write to temp, then atomic rename
with tempfile.NamedTemporaryFile(delete=False) as tmp:
  tmp.write(data)
os.replace(tmp.name, "config.json")
💡 This pattern is used by databases, editors (VS Code), and config managers. Never write directly to important files.
10 Why does csv.writer need newline="" on Windows? ▼

The CSV module handles line endings itself. Without newline="", Python's text mode ALSO translates newlines — resulting in double newlines (\r\r\n) on Windows, which shows up as blank rows between your data.

newline="" tells Python: "don't do any newline translation — let the csv module handle it." Always include it when opening files for csv reading or writing.

💡 This is a Windows-specific issue but including newline="" is harmless on macOS/Linux — always add it for portability.
